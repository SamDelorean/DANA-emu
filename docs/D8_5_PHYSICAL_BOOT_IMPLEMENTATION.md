## Implemented behavior

- Reuse MAME `GENERIC_SOCKET` with its existing read-only ROM image interface, raw byte storage and reset-on-load behavior. `-rom PRIVATE_FULL_FLASH.bin` selects physical boot; the existing `-quickload PRIVATE_024C.dana` still selects R-direct. Mounting both is rejected before either can run. File selection is available through the existing MAME image UI; no new GUI is introduced.
- Accept a complete, contiguous, big-endian bus-order **linear read-array image**, with its original vectors at byte zero. File length declares the supplied array geometry: power of two in the VZ CSA decode range, 128 KiB–16 MiB. This is **not a claim that a Dana contains any particular capacity**. Check an aligned, nonzero reset PC outside internal MMIO and reject the known DANARAM1 wrapper. Do not require an updater/PalmCard header at any physical Flash offset: its location in updater payloads does not prove the full dump layout. These checks establish structure, not authenticity or ownership. Require an independently identified full dump before native qualification.
- Read original bytes exactly: no padding, endian conversion, updater extraction, fabricated boot block, relocation or firmware writes. Reject nonmatching/short input and incompatible socket allocation before reading into it. Existing updater payload lengths in Dana-OS3K are not treated as complete physical Flash dumps.
- A MAME memory view keeps the original 4 MiB RAM mapping in R-direct. Physical mode selects read-array/reset decoding instead. CPU device reset acquires words at 0, 2, 4, 6 from the firmware. The physical path does not write vectors, SSP, PC, SR or general CPU registers, does not clear RAM and does not call CPU `reset()` to synthesize an entry. The existing RAM loader's declared synthetic bootstrap remains exclusive to R-direct.
- Implement VZ CSA reset boot selection, then guest-programmed CSA and CSD base/enable/size decode. No fixed Palm high-ROM base is invented. The supplied linear array's address lines determine reset aliases; configured CSA windows must cover that array and use supported aligned group decode. CSD accesses use the existing RAM share, limited to its existing 4 MiB. DRAM-backed accesses require a documented controller enable. SDRAM precharge/mode writes are commands, not data stores.
- Add physical-only SCR, fixed VZ chip ID, CS group/select/control/EMU and DRAM register decoding. Apply the D0.2 manufacturer/addendum corrections: CSCTRL2=1000, CSCTRL3=9C00 and SDCTRL=003C. Keep physical Port C FF and PFSEL 87 distinct from synthetic R-direct 00/C5. Other GPIO latch defaults are explicitly the pinned open VZ reference model, not measured Dana board electrical inputs. The physical entry reuses the existing PLL/SYSCLK formula for the CPU and Timer1; PLLCR divisors/lock timing, physical retuning and complete electrical reset equivalence remain unqualified.
- Unsupported Flash commands, bank/protection/extended-CS modes, overlapping windows and previously unmapped MMIO terminate execution with `DANA_PHYSICAL_BLOCKED`; MMIO also records address/lane mask. Return data after a diagnostic stop is not a successful hardware response. Side-effect-disabled debugger inspection does not manufacture a CPU block event. NOR manufacturer IDs, erase/program completion and nonexistent peripherals are never synthesized.
- Save controller/view/profile state and bind physical save restoration to the currently loaded immutable Flash bytes. Reject a saved state from another profile or image. Unloading firmware stops the CPU rather than falling through into stale ROM/RAM; restart with the intended single image to change profiles.
